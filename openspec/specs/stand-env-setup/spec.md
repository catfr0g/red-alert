## Purpose

Скрипт в `script/` логинится на тестовый стенд, выпускает API-ключи выбранных пользователей и пишет их в локальный `.env`. Команда `red-alert attack` только читает уже готовые переменные.

## Requirements

### Requirement: Скрипт выпускает ключи стенда в .env

СИСТЕМА ДОЛЖНА (MUST) предоставлять скрипт в каталоге `script/`, который авторизует указанных тестовых пользователей стенда, выпускает для каждого долгоживущий API-ключ и записывает ключи в локальный `.env` (или файл из `--env-file`). Команда `red-alert attack` при этом не меняется и по-прежнему только читает уже готовые переменные.

#### Scenario: Успешная подготовка двух пользователей

- **WHEN** пользователь запускает скрипт с доступными Keycloak и agent-api и списком из двух пользователей
- **THEN** система получает токен и ключ для каждого, пишет `RED_ALERT_API_KEY` и `RED_ALERT_VICTIM_API_KEY` в `.env` и завершается с кодом 0

#### Scenario: Запуск по умолчанию

- **WHEN** пользователь запускает скрипт без `--users` и без `RED_ALERT_STAND_USERS`
- **THEN** система выпускает ключи для `client1001` (атакующий) и `client1002` (жертва)

### Requirement: Параметры стенда задаются флагами или окружением

СИСТЕМА ДОЛЖНА (MUST) брать адрес agent-api, адрес Keycloak, realm, client id, client secret, список пользователей и общий пароль из флагов или переменных окружения. Флаг перекрывает переменную. Без флага и переменной используются значения учебного стенда: `http://localhost:8600`, `http://localhost:8180`, `genai-stand`, `streamlit-ui`, `streamlit-ui-secret`, пользователи `client1001,client1002`. Если общий пароль не задан, пароль каждого пользователя равен его логину.

#### Scenario: Цель и Keycloak из окружения

- **WHEN** заданы `RED_ALERT_TARGET` и `RED_ALERT_KEYCLOAK_URL`, а соответствующие флаги не переданы
- **THEN** система ходит на эти адреса

#### Scenario: Флаг перекрывает окружение

- **WHEN** задана `RED_ALERT_TARGET=http://old:8600` и передан `--target http://new:8600`
- **THEN** система обращается к `http://new:8600`

#### Scenario: Пароль равен логину

- **WHEN** не заданы `--password` и `RED_ALERT_STAND_PASSWORD`
- **THEN** в password grant для пользователя `client1001` уходит пароль `client1001`

### Requirement: Дополнительные пользователи сохраняются отдельно

СИСТЕМА ДОЛЖНА (MUST) при списке длиннее двух записать первого пользователя в `RED_ALERT_API_KEY`, второго в `RED_ALERT_VICTIM_API_KEY`, а каждого следующего в `RED_ALERT_USER_<username>_API_KEY`. Список короче двух имён — код 2 без HTTP.

#### Scenario: Три пользователя

- **WHEN** пользователь указывает `--users client1001,client1002,client1003`
- **THEN** в `.env` есть `RED_ALERT_API_KEY`, `RED_ALERT_VICTIM_API_KEY` и `RED_ALERT_USER_client1003_API_KEY`

#### Scenario: Один пользователь

- **WHEN** пользователь указывает `--users client1001`
- **THEN** система не выполняет HTTP, пишет ошибку в stderr и завершается с кодом 2

### Requirement: Запись .env не затирает чужие переменные

СИСТЕМА ДОЛЖНА (MUST) обновлять только переменные ключей стенда. Комментарии и остальные ключи (в том числе `OPENAI_API_KEY`) сохраняются. Совпавшую переменную система заменяет на месте; отсутствующую дописывает. Если `.env` нет, а рядом есть `.env.example`, система копирует пример и затем обновляет ключи. Запись выполняется только после успешного выпуска всех запрошенных ключей.

#### Scenario: Существующий .env сохраняет ключ планировщика

- **WHEN** в `.env` уже есть `OPENAI_API_KEY=sk-planner` и устаревший `RED_ALERT_API_KEY`
- **THEN** после успеха `OPENAI_API_KEY` не меняется, а `RED_ALERT_API_KEY` заменяется новым значением

#### Scenario: Сбой второго пользователя не портит файл

- **WHEN** ключ первого пользователя получен, а выпуск ключа второго завершился ошибкой HTTP
- **THEN** `.env` остаётся таким, каким был до запуска, и процесс завершается с кодом 1

#### Scenario: Нет .env, есть .env.example

- **WHEN** `.env` отсутствует, а `.env.example` есть
- **THEN** система создаёт `.env` из примера и записывает в него выпущенные ключи

### Requirement: Секреты не печатаются

СИСТЕМА ДОЛЖНА (MUST) не печатать в stdout и stderr сырые API-ключи, пароли пользователей и client secret. Допустимы логины и укороченный префикс ключа.

#### Scenario: Успешный запуск без сырого ключа

- **WHEN** скрипт успешно записал ключи в `.env`
- **THEN** в выводе нет полного значения ключа и нет client secret

#### Scenario: Ошибка Keycloak без пароля в stderr

- **WHEN** Keycloak отвечает ошибкой на password grant
- **THEN** в stderr нет пароля пользователя

### Requirement: Ошибка ввода останавливает скрипт без HTTP

СИСТЕМА ДОЛЖНА (MUST) при невалидном вводе (пустой список после разбора, пустой `--target`, пустой `--keycloak-url`) завершаться с кодом 2 и не выполнять HTTP-запросы.

#### Scenario: Пустой адрес стенда

- **WHEN** пользователь передаёт `--target` с пустым значением
- **THEN** система не выполняет HTTP, пишет ошибку в stderr и завершается с кодом 2
