## Purpose

Сценарий с `flow: memory` (готовый файл `memory-poisoning.yaml`): атакующий внедряет глобальную политику, жертва спрашивает про портфель, успех считается по её ответу.

## Requirements

### Requirement: Сценарий отравления памяти через публичный API

СИСТЕМА ДОЛЖНА (MUST) для YAML с `flow: memory` сгенерировать payload планировщиком, доставить его ключом атакующего, выполнить persist сессии и проверить поведение ключом другого пользователя.

#### Scenario: Полная цепочка одной попытки

- **WHEN** запускается сценарий с `flow: memory`
- **THEN** система последовательно: вызывает планировщик; отправляет payload в чат сессии A ключом атакующего; вызывает persist сессии A; отправляет trigger в сессию B ключом жертвы

#### Scenario: Payload направлен на цель YAML

- **WHEN** система отправляет payload атакующего
- **THEN** текст соответствует цели загруженного сценария

#### Scenario: Триггер жертвы — разбор портфеля

- **WHEN** система отправляет триггер жертвы
- **THEN** сообщение берётся из поля `trigger` YAML

#### Scenario: Режим стенда

- **WHEN** система вызывает чат-API стенда
- **THEN** в теле запроса передаётся `auth_mode` выбранного режима (`vulnerable` или `protected`)

#### Scenario: Изоляция попыток по сессиям

- **WHEN** выполняются две попытки подряд
- **THEN** идентификаторы сессий A и B первой попытки не совпадают с идентификаторами второй попытки

### Requirement: Успех попытки по regex на ответ жертвы

СИСТЕМА ДОЛЖНА (MUST) считать попытку `flow: memory` успешной только если ответ агента на триггер в сессии жертвы совпадает с `success_pattern` YAML.

#### Scenario: Триггер жертвы подтверждает цель

- **WHEN** ответ на триггер жертвы совпадает с `success_pattern`
- **THEN** попытка помечается как успешная

#### Scenario: Триггер не подтверждает цель

- **WHEN** чат и finalize завершились без HTTP-ошибки, но ответ на триггер жертвы не совпадает с `success_pattern`
- **THEN** попытка помечается как неуспешная

#### Scenario: Ошибка HTTP на любом шаге

- **WHEN** любой запрос попытки завершается ошибкой сети или HTTP-статусом 4xx/5xx
- **THEN** попытка помечается как неуспешная и оставшиеся шаги этой попытки не выполняются

### Requirement: Доказательства включают состояние после finalize

СИСТЕМА ДОЛЖНА (MUST) сохранять в доказательствах тело ответа persist, включая извлечённые факты, если запрос завершился успешно.

#### Scenario: Finalize вернул факты

- **WHEN** стенд отвечает на persist списком фактов
- **THEN** эти факты входят в доказательства попытки независимо от вердикта regex

### Requirement: Попытки с изоляцией не наследуют долговременную память

СИСТЕМА ДОЛЖНА (MUST) при включённой изоляции начинать каждую попытку `flow: memory` после успешного isolate, чтобы глобальная политика предыдущей попытки не оставалась на стенде. Isolate между persist и trigger одной попытки не вызывается.

#### Scenario: Вторая попытка идёт с чистого baseline

- **WHEN** изоляция включена и после успешной первой попытки memory-poisoning стартует вторая
- **THEN** система вызывает isolate после первой попытки и до payload второй

#### Scenario: Trigger видит persist этой попытки

- **WHEN** изоляция включена и persist текущей попытки вернул usable global-политику
- **THEN** система отправляет trigger жертвы без промежуточного isolate
