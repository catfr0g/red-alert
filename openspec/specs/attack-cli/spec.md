## Purpose

Команда `red-alert attack` запускает один YAML-сценарий или весь каталог против стенда, читает цель и ключи из аргументов или окружения и может записать JSON-отчёт в UTF-8 файл.

## Requirements

### Requirement: Запуск атаки из командной строки

СИСТЕМА ДОЛЖНА (MUST) предоставлять команду `red-alert attack` с параметрами цели, ключа атакующего, ключа жертвы, сценария (имя YAML или путь), необязательного каталога атак, числа попыток и необязательного файла JSON-отчёта.

#### Scenario: Успешный запуск с полными аргументами

- **WHEN** пользователь выполняет `red-alert attack --target <url> --api-key <attacker> --victim-api-key <victim> --scenario memory-poisoning`
- **THEN** система запускает сценарий против указанного URL и печатает краткий итог прогона

#### Scenario: Цель берётся из окружения

- **WHEN** аргумент `--target` не задан и задана переменная `RED_ALERT_TARGET`
- **THEN** система использует значение переменной как базовый URL стенда

#### Scenario: Цель по умолчанию

- **WHEN** не заданы ни `--target`, ни `RED_ALERT_TARGET`
- **THEN** система использует `http://localhost:8600`

#### Scenario: Ключ атакующего берётся из окружения

- **WHEN** аргумент `--api-key` не задан и задана переменная `RED_ALERT_API_KEY`
- **THEN** система использует значение переменной как Bearer-ключ атакующего

#### Scenario: Ключ жертвы берётся из окружения

- **WHEN** аргумент `--victim-api-key` не задан и задана переменная `RED_ALERT_VICTIM_API_KEY`
- **THEN** система использует значение переменной как Bearer-ключ жертвы

#### Scenario: Ключ атакующего отсутствует

- **WHEN** не заданы ни `--api-key`, ни `RED_ALERT_API_KEY`
- **THEN** система не выполняет HTTP-запросы, пишет ошибку в stderr и завершается с кодом 2

#### Scenario: Ключ жертвы отсутствует

- **WHEN** не заданы ни `--victim-api-key`, ни `RED_ALERT_VICTIM_API_KEY`
- **THEN** система не выполняет HTTP-запросы, пишет ошибку в stderr и завершается с кодом 2

#### Scenario: Ключи совпадают

- **WHEN** ключ атакующего совпадает с ключом жертвы
- **THEN** система не выполняет HTTP-запросы, пишет ошибку в stderr и завершается с кодом 2

#### Scenario: Каталог атак из окружения

- **WHEN** задана `RED_ALERT_ATTACKS_DIR` и `--attacks-dir` не передан
- **THEN** система ищет YAML в этом каталоге

#### Scenario: Неизвестный сценарий

- **WHEN** пользователь указывает `--scenario` со значением, для которого нет YAML
- **THEN** система не выполняет HTTP-запросы, пишет ошибку в stderr и завершается с кодом 2

#### Scenario: Отчёт записан в UTF-8 JSON

- **WHEN** пользователь указывает `--output attack-report.json` и прогон завершается
- **THEN** система пишет в этот путь JSON с трейсами успешных попыток в кодировке UTF-8

### Requirement: Прогон всего каталога по умолчанию

СИСТЕМА ДОЛЖНА (MUST) при отсутствии `--scenario` загрузить все YAML из каталога атак в алфавитном порядке имён и выполнить каждый сценарий с указанным `--attempts`. Явный `--scenario` запускает только выбранный файл. Пустой каталог или невалидный YAML останавливают прогон с кодом 2 без HTTP.

#### Scenario: Запуск без --scenario

- **WHEN** пользователь выполняет `red-alert attack` без `--scenario` и в каталоге есть несколько YAML
- **THEN** система выполняет каждый сценарий по очереди, в прогрессе видно имя текущего, в итоге есть все имена

#### Scenario: Явный один сценарий

- **WHEN** пользователь указывает `--scenario memory-poisoning`
- **THEN** система выполняет только этот сценарий

#### Scenario: Пустой каталог

- **WHEN** `--scenario` не задан и в каталоге нет YAML
- **THEN** система не выполняет HTTP, пишет ошибку в stderr и завершается с кодом 2

#### Scenario: Попытки на каждый сценарий

- **WHEN** пользователь указывает `--attempts 3` без `--scenario` и в каталоге два YAML
- **THEN** система делает три попытки первого сценария и три попытки второго

### Requirement: Несколько попыток для ASR

СИСТЕМА ДОЛЖНА (MUST) выполнять указанное число попыток выбранного сценария и учитывать каждую попытку в ASR.

#### Scenario: Несколько попыток

- **WHEN** пользователь указывает `--attempts 3` и один сценарий
- **THEN** система выполняет сценарий три раза с отдельными идентификаторами сессий и считает ASR по трём попыткам

#### Scenario: Некорректное число попыток

- **WHEN** пользователь указывает `--attempts` меньше 1
- **THEN** система не выполняет HTTP-запросы и завершается с кодом 2

### Requirement: Для атаки нужен LLM планировщика

СИСТЕМА ДОЛЖНА (MUST) читать `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `MODEL` и `MAX_TOKENS` из окружения или `.env`. Без ключа и модели планировщика атака не запускается.

#### Scenario: Ключ планировщика отсутствует

- **WHEN** не задана `OPENAI_API_KEY`, а ключи стенда заданы
- **THEN** система не выполняет HTTP-запросы, пишет ошибку в stderr и завершается с кодом 2

#### Scenario: Модель отсутствует

- **WHEN** не задана `MODEL`, а `OPENAI_API_KEY` задан
- **THEN** система не выполняет HTTP-запросы, пишет ошибку в stderr и завершается с кодом 2

#### Scenario: Базовый URL и лимит по умолчанию

- **WHEN** заданы `OPENAI_API_KEY` и `MODEL`, а `OPENAI_BASE_URL` и `MAX_TOKENS` не заданы
- **THEN** система использует `https://openrouter.ai/api/v1` и `MAX_TOKENS=2048`

#### Scenario: Некорректный MAX_TOKENS

- **WHEN** `MAX_TOKENS` не целое число >= 1
- **THEN** система не выполняет HTTP-запросы, пишет ошибку в stderr и завершается с кодом 2

### Requirement: Режим debug для полного лога

СИСТЕМА ДОЛЖНА (MUST) включать полный лог атаки по флагу `--debug` или переменной `RED_ALERT_DEBUG` со значениями `1`, `true`, `yes` или `on`.

#### Scenario: Флаг --debug

- **WHEN** пользователь запускает `red-alert attack --debug`
- **THEN** система печатает на stderr каждый шаг попытки: имя, актор, URL, статус или ошибку, тела запроса и ответа

#### Scenario: Переменная окружения

- **WHEN** задана `RED_ALERT_DEBUG=1` и флаг `--debug` не передан
- **THEN** система включает тот же полный лог, что и с `--debug`

#### Scenario: Обычный режим

- **WHEN** флаг `--debug` не передан и `RED_ALERT_DEBUG` не задана
- **THEN** система не печатает тела запросов и ответов каждого шага на stderr

#### Scenario: Секреты скрыты в debug

- **WHEN** включён debug и в шагах есть ключи стенда или планировщика
- **THEN** в stderr нет этих значений в открытом виде

### Requirement: Ключи не попадают в вывод

СИСТЕМА ДОЛЖНА (MUST) не печатать секреты API-ключей атакующего, жертвы, планировщика и Langfuse в stdout и stderr.

#### Scenario: Отчёт после прогона

- **WHEN** прогон завершается и печатается отчёт
- **THEN** в выводе нет значений ключей стенда и `OPENAI_API_KEY` в открытом виде

#### Scenario: Секрет Langfuse скрыт

- **WHEN** экспорт включён и в stderr или stdout есть диагностика
- **THEN** в выводе нет значения `LANGFUSE_SECRET_KEY` в открытом виде

### Requirement: Экспорт в Langfuse включается из окружения

СИСТЕМА ДОЛЖНА (MUST) включать запись трейсов в Langfuse по переменной `RED_ALERT_LANGFUSE` со значениями `1`, `true`, `yes` или `on`. При включении обязательны `LANGFUSE_PUBLIC_KEY` и `LANGFUSE_SECRET_KEY`. `LANGFUSE_BASE_URL` по умолчанию `http://localhost:3000`. Без переменной экспорт выключен, даже если ключи заданы.

#### Scenario: Флаг включает экспорт

- **WHEN** заданы `RED_ALERT_LANGFUSE=1`, ключи Langfuse и доступный сервер
- **THEN** система перед атакой обращается к Langfuse и во время попыток пишет граф через CallbackHandler

#### Scenario: Ключи без флага ничего не включают

- **WHEN** заданы `LANGFUSE_PUBLIC_KEY` и `LANGFUSE_SECRET_KEY`, а `RED_ALERT_LANGFUSE` не задана
- **THEN** система не обращается к Langfuse и выполняет атаку как обычно

#### Scenario: Нет ключа при включённом флаге

- **WHEN** задана `RED_ALERT_LANGFUSE=1` и нет `LANGFUSE_SECRET_KEY`
- **THEN** система не выполняет HTTP к стенду, пишет ошибку в stderr и завершается с кодом 2

#### Scenario: Базовый URL по умолчанию

- **WHEN** экспорт включён, ключи заданы, а `LANGFUSE_BASE_URL` нет
- **THEN** система использует `http://localhost:3000`

### Requirement: Сбой Langfuse останавливает прогон

СИСТЕМА ДОЛЖНА (MUST) если экспорт включён и Langfuse недоступен, отклоняет ключи или не принимает запись — не продолжать атаку молча: написать ошибку в stderr и завершиться с кодом 1. Обычный JSON-отчёт атаки в этом случае не печатать. Код 2 по-прежнему только для ошибок ввода.

#### Scenario: Langfuse недоступен до атаки

- **WHEN** экспорт включён, ключи заданы, а Langfuse не отвечает на проверку доступности
- **THEN** система не вызывает стенд, пишет ошибку в stderr и завершается с кодом 1

#### Scenario: Запись попытки не удалась

- **WHEN** экспорт включён, проверка доступности прошла, а запись графа или дозапись тегов/score в Langfuse не удалась
- **THEN** система прекращает дальнейшие попытки, пишет ошибку в stderr и завершается с кодом 1

#### Scenario: Прогон без Langfuse при ASR 0% по-прежнему код 0

- **WHEN** экспорт выключен и ни одна попытка не успешна
- **THEN** процесс завершается с кодом 0 и отчёт напечатан
