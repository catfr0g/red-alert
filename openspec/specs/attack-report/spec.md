## Purpose

Краткий итог прогона в консоли и JSON с трейсами. При `--output` JSON пишется в UTF-8 файл.

## Requirements

### Requirement: Отчёт с вердиктом и ASR

СИСТЕМА ДОЛЖНА (MUST) печатать краткий итог прогона: число успешных попыток, число всех попыток и ASR.

#### Scenario: Все попытки успешны

- **WHEN** выполнены две попытки и обе успешны
- **THEN** итог показывает 2 успешные из 2 и ASR 100%

#### Scenario: Часть попыток успешна

- **WHEN** выполнены две попытки и успешна только одна
- **THEN** итог показывает 1 успешную из 2 и ASR 50%

#### Scenario: Нет успешных попыток

- **WHEN** выполнена одна неуспешная попытка
- **THEN** итог показывает 0 успешных из 1, ASR 0% и код выхода 0

### Requirement: Отчёт по нескольким сценариям

СИСТЕМА ДОЛЖНА (MUST) при прогоне нескольких сценариев печатать итог каждого (имя, успешные попытки, ASR) и суммарный ASR по всем попыткам. JSON одного сценария остаётся объектом с полем `scenario`. JSON нескольких сценариев ДОЛЖЕН (MUST) содержать `target`, суммарные `successful`, `total`, `asr` и массив `runs` с отчётом каждого сценария.

#### Scenario: Два сценария в одном JSON

- **WHEN** прогон без `--scenario` завершается и задан `--output`
- **THEN** файл содержит `runs` с именем каждого сценария и суммарный `asr`

#### Scenario: Один сценарий сохраняет прежний JSON

- **WHEN** задан `--scenario` с одним YAML
- **THEN** JSON содержит поле `scenario` и не содержит `runs`

### Requirement: Цепочка шагов в отчёте

СИСТЕМА ДОЛЖНА (MUST) класть полную цепочку шагов успешной попытки в JSON-трейс: имя, URL без секрета, тело запроса без заголовка авторизации и тело ответа. При включённой изоляции первым шагом попытки является `isolate`.

#### Scenario: Успешная попытка содержит полную цепочку

- **WHEN** попытка прошла payload-сообщения, persist и trigger, изоляция включена и попытка признана успешной
- **THEN** в JSON `traces` есть шаги isolate, payload, persist и trigger в этом порядке с запросами и ответами

#### Scenario: Неуспешная попытка не попадает в traces

- **WHEN** попытка завершилась без успеха и debug выключен
- **THEN** её шаги отсутствуют в JSON `traces`

#### Scenario: Обрыв цепочки при ошибке

- **WHEN** payload вернул HTTP 500 и debug выключен
- **THEN** в итоге попытки виден шаг payload с ошибкой, последующих persist и trigger нет, traces пустой

#### Scenario: Без изоляции шага isolate нет

- **WHEN** изоляция выключена и попытка успешна
- **THEN** в JSON `traces` нет шага `isolate`

### Requirement: Шаг adapt в доказательствах успешной попытки

СИСТЕМА ДОЛЖНА (MUST) включать в JSON-трейс успешной попытки шаг `adapt` с актором `planner` до шага payload: URL планировщика, тело запроса без заголовка авторизации и тело ответа. При включённой изоляции `adapt` идёт сразу после `isolate`.

#### Scenario: Успешная попытка начинается с adapt

- **WHEN** попытка успешна, изоляция включена и пишется JSON `traces`
- **THEN** шаги трейса начинаются с `isolate`, затем `adapt`, за ним payload, persist и trigger

#### Scenario: Секрет планировщика скрыт в трейсе

- **WHEN** отчёт содержит шаг `adapt`
- **THEN** в JSON нет значения `OPENAI_API_KEY` и нет заголовка `Authorization`

### Requirement: JSON-трейсы неуспешных попыток в debug

СИСТЕМА ДОЛЖНА (MUST) в режиме debug включать в JSON `traces` все попытки, в том числе неуспешные, с полной цепочкой шагов.

#### Scenario: Неуспешная попытка попадает в traces

- **WHEN** включён debug и попытка завершилась без успеха
- **THEN** в JSON `traces` есть эта попытка и её шаги

#### Scenario: Без debug неуспешная попытка не в traces

- **WHEN** debug выключен и попытка неуспешна
- **THEN** её шаги отсутствуют в JSON `traces`

### Requirement: Прогресс выполнения в консоли

СИСТЕМА ДОЛЖНА (MUST) во время прогона показывать ход попыток, текущий шаг и имя текущего сценария.

#### Scenario: Несколько попыток

- **WHEN** пользователь запускает атаку с `--attempts` больше 1
- **THEN** в ходе выполнения видно продвижение по попыткам

### Requirement: Коды выхода CLI

СИСТЕМА ДОЛЖНА (MUST) завершать успешный прогон кодом 0 даже при ASR 0% и использовать код 2 только для ошибок ввода.

#### Scenario: Прогон с нулевым ASR

- **WHEN** сценарий выполнен и ни одна попытка не успешна
- **THEN** процесс завершается с кодом 0 и отчёт напечатан

#### Scenario: Ошибка ввода

- **WHEN** отсутствует ключ атакующего, отсутствует ключ жертвы, ключи совпадают или указан неизвестный сценарий
- **THEN** процесс завершается с кодом 2 и отчёт об атаке не печатается

### Requirement: Файл отчёта в UTF-8

СИСТЕМА ДОЛЖНА (MUST) при заданном `--output` сохранять JSON-отчёт в указанный файл в UTF-8 без зависимости от кодировки оболочки.

#### Scenario: Секреты скрыты и в файле

- **WHEN** отчёт пишется в файл через `--output`
- **THEN** в файле нет значений API-ключей в открытом виде

### Requirement: Режим стенда в отчёте

СИСТЕМА ДОЛЖНА (MUST) печатать `auth_mode` в кратком итоге каждого прогона и класть его в JSON. Если в одном запуске есть и `vulnerable`, и `protected`, система ДОЛЖНА (MUST) напечатать ASR отдельно по каждому режиму.

#### Scenario: JSON содержит auth_mode

- **WHEN** прогон одного сценария в `protected` завершается
- **THEN** JSON содержит `"auth_mode": "protected"`

#### Scenario: Сравнение двух режимов

- **WHEN** задан `--auth-mode both`
- **THEN** в консоли есть ASR для `vulnerable` и для `protected`

### Requirement: Режим изоляции виден в итоге и JSON

СИСТЕМА ДОЛЖНА (MUST) печатать режим изоляции (`on` или `off`) в кратком итоге прогона и класть поле `isolation` с тем же значением в JSON-отчёт каждого run.

#### Scenario: Итог показывает isolation on

- **WHEN** прогон завершается с изоляцией по умолчанию
- **THEN** краткий итог содержит `on` для режима изоляции и в JSON run есть `isolation` со значением `on`

#### Scenario: Итог показывает isolation off

- **WHEN** прогон завершается с `--isolate off`
- **THEN** краткий итог содержит `off` для режима изоляции и в JSON run есть `isolation` со значением `off`
