## Purpose

Red Alert вызывает свой OpenAI-совместимый LLM, чтобы написать payload. Цель и примеры берутся из YAML сценария.

## Requirements

### Requirement: Payload пишет свой LLM Red Alert

СИСТЕМА ДОЛЖНА (MUST) перед каждым inject вызвать OpenAI-совместимый чат-API планировщика (`OPENAI_BASE_URL`, `OPENAI_API_KEY`, `MODEL`, `MAX_TOKENS`) и отправить на стенд только полученный текст пользовательского сообщения. Цель и примеры в запросе берутся из загруженного YAML, а не из зашитого кейса YDEX.

#### Scenario: Первый inject берёт текст у планировщика

- **WHEN** начинается попытка
- **THEN** система сначала вызывает планировщик, затем отправляет его ответ как единственное payload-сообщение атакующего в новой сессии A

#### Scenario: Цель из сценария

- **WHEN** планировщик собирает сообщения для LLM
- **THEN** пользовательское сообщение содержит поле `goal` текущего YAML

#### Scenario: Повтор inject после неудачного finalize

- **WHEN** finalize не вернул usable global-политику и лимит inject не исчерпан
- **THEN** система снова вызывает планировщик, передаёт ему факты последнего finalize и отправляет новый сгенерированный текст в новой сессии A

#### Scenario: Следующая попытка видит исход предыдущей

- **WHEN** выполняется вторая попытка после первой того же сценария
- **THEN** запрос планировщика содержит краткую заметку о результате первой попытки

#### Scenario: Ошибка сети или HTTP обрывает попытку

- **WHEN** вызов LLM планировщика завершается ошибкой сети или HTTP 4xx/5xx
- **THEN** попытка неуспешна, шаг `adapt` содержит ошибку, inject на стенд в этом цикле не выполняется

#### Scenario: Пустой ответ повторяется

- **WHEN** планировщик вернул успешный HTTP, но текст сообщения пустой
- **THEN** система повторяет запрос к LLM ещё до двух раз в рамках того же шага `adapt`

#### Scenario: После пустых ответов берётся пример сценария

- **WHEN** после повторов текст всё ещё пустой и у сценария есть примеры payload
- **THEN** система отправляет на стенд первый пример и не помечает попытку ошибкой планировщика

### Requirement: Планировщик не подменяет стенд

СИСТЕМА ДОЛЖНА (MUST) вызывать LLM планировщика отдельно от `agent-api`: другой базовый URL и другой ключ. Ключ планировщика не передаётся стенду.

#### Scenario: Разные контуры

- **WHEN** система генерирует payload и затем шлёт его на стенд
- **THEN** запрос планировщика идёт на `OPENAI_BASE_URL` с `OPENAI_API_KEY`, а запрос стенда — на `RED_ALERT_TARGET` с ключом атакующего
