## MODIFIED Requirements

### Requirement: Отчёт с вердиктом и ASR

СИСТЕМА ДОЛЖНА (MUST) печатать краткий итог прогона: число успешных попыток, число всех попыток и ASR.

#### Scenario: Все попытки успешны

- **WHEN** выполнены две попытки и обе успешны
- **THEN** итог показывает 2 успешные из 2 и ASR 100%

#### Scenario: Часть попыток успешна

- **WHEN** выполнены две попытки и успешна только одна
- **THEN** итог показывает 1 успешную из 2 и ASR 50%

#### Scenario: Нет успешных попыток

- **WHEN** выполнена одна неуспешная попытка
- **THEN** итог показывает 0 успешных из 1, ASR 0% и код выхода 0

### Requirement: Цепочка шагов в отчёте

СИСТЕМА ДОЛЖНА (MUST) класть полную цепочку шагов успешной попытки в JSON-трейс: имя, URL без секрета, тело запроса без заголовка авторизации и тело ответа.

#### Scenario: Успешная попытка содержит полную цепочку

- **WHEN** попытка прошла payload-сообщения, finalize и trigger и признана успешной
- **THEN** в JSON `traces` есть шаги payload, finalize и trigger в этом порядке с запросами и ответами

#### Scenario: Неуспешная попытка не попадает в traces

- **WHEN** попытка завершилась без успеха
- **THEN** её шаги отсутствуют в JSON `traces`

#### Scenario: Обрыв цепочки при ошибке

- **WHEN** payload вернул HTTP 500
- **THEN** в итоге попытки виден шаг payload с ошибкой, последующих finalize и trigger нет, traces пустой

### Requirement: Файл отчёта в UTF-8

СИСТЕМА ДОЛЖНА (MUST) при заданном `--output` сохранять JSON-отчёт в указанный файл в UTF-8 без зависимости от кодировки оболочки.

#### Scenario: Секреты скрыты и в файле

- **WHEN** отчёт пишется в файл через `--output`
- **THEN** в файле нет значений API-ключей в открытом виде

## ADDED Requirements

### Requirement: Прогресс выполнения в консоли

СИСТЕМА ДОЛЖНА (MUST) во время прогона показывать ход попыток и текущий шаг.

#### Scenario: Несколько попыток

- **WHEN** пользователь запускает атаку с `--attempts` больше 1
- **THEN** в ходе выполнения видно продвижение по попыткам
