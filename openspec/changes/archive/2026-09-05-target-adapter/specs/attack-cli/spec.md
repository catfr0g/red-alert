## ADDED Requirements

### Requirement: Режим изоляции задаётся флагом или окружением

СИСТЕМА ДОЛЖНА (MUST) принимать `--isolate` и переменную `RED_ALERT_ISOLATE` со значениями `on` и `off` без учёта регистра. Флаг перекрывает переменную. Если ни флаг, ни переменная не заданы, режим равен `on`. Невалидное значение — код 2, без HTTP к стенду.

#### Scenario: Значение по умолчанию

- **WHEN** пользователь запускает `red-alert attack` без `--isolate` и без `RED_ALERT_ISOLATE`
- **THEN** система включает изоляцию и вызывает isolate до каждой попытки

#### Scenario: Флаг выключает изоляцию

- **WHEN** пользователь указывает `--isolate off`
- **THEN** система не вызывает isolate и продолжает прогон

#### Scenario: Переменная задаёт режим

- **WHEN** задана `RED_ALERT_ISOLATE=off` и флаг `--isolate` не передан
- **THEN** система выключает изоляцию так же, как с `--isolate off`

#### Scenario: Флаг перекрывает переменную

- **WHEN** заданы `RED_ALERT_ISOLATE=off` и `--isolate on`
- **THEN** система включает изоляцию

#### Scenario: Невалидное значение

- **WHEN** пользователь указывает `--isolate maybe`
- **THEN** система не выполняет HTTP-запросы, пишет ошибку в stderr и завершается с кодом 2

### Requirement: Выключенная изоляция сопровождается предупреждением

СИСТЕМА ДОЛЖНА (MUST) если изоляция выключена, один раз до первого запроса к стенду написать в stderr предупреждение: попытки могут наследовать память предыдущих прогонов, ASR не независим. Прогон при этом продолжается.

#### Scenario: Warning при isolate off

- **WHEN** пользователь запускает атаку с `--isolate off`
- **THEN** в stderr есть предупреждение про наследование памяти и не независимый ASR, и прогон выполняется

#### Scenario: Без warning при isolate on

- **WHEN** изоляция включена по умолчанию
- **THEN** система не пишет это предупреждение
