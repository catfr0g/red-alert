## Context

Сейчас `AttackProgress` показывает только имя шага, а `format_json_report` отбрасывает неуспешные попытки. Для адаптивной атаки этого мало: нужно видеть промпт планировщика, ответ агента и finalize.

## Goals / Non-Goals

**Goals:**

- Включить полный лог флагом или переменной окружения.
- Печатать каждый шаг на stderr в момент выполнения.
- Класть все попытки в JSON `traces` только в debug.
- Маскировать ключи стенда и планировщика.

**Non-Goals:**

- Библиотека logging и уровни DEBUG/INFO.
- Отдельный debug-файл.
- Усечение больших тел ответа.

## Decisions

### Один переключатель

`--debug` или `RED_ALERT_DEBUG` из `{1, true, yes, on}`. Флаг сильнее выключателя по умолчанию: если передан `--debug`, режим включён. Переменная нужна, чтобы не менять командную строку.

Альтернатива: только флаг. Не выбрано: для повторных прогонов удобнее `.env`.

### stderr для шагов, stdout для итога

Краткий ASR и JSON остаются на stdout. Полные шаги идут в stderr, чтобы `>` не смешивал лог с отчётом.

В debug прогресс-бар не запускается: rich Progress затирает многострочный лог.

### JSON в debug включает failures

Иначе `--output` в debug всё равно прячет упавшую цепочку. Обычный режим без изменений: traces только success.

## Risks / Trade-offs

- [Большие ответы LLM засоряют терминал] → Это цель debug. Обычный режим короткий.
- [Секрет в теле ответа стенда] → Та же маскировка, что в JSON.

## Migration Plan

Без флага ничего не меняется. Откат — убрать `--debug` и чтение `RED_ALERT_DEBUG`.
