## Why

Нужен первый рабочий прототип Red Alert: специалист кибербезопасности должен одной командой прогнать сценарий отравления памяти на тестовом стенде GenAI Investment Assistant и получить воспроизводимый отчёт. Сейчас в репозитории нет исполняемого контура, зависимостей и тестов — только описание продукта.

## What Changes

- Добавить CLI-команду запуска атаки на внешний стенд по публичным HTTP-эндпоинтам.
- Реализовать один фиксированный сценарий: внедрить глобальную политику через диалог атакующего, финализировать сессию и проверить её на **другом пользователе** стенда.
- Сохранять цепочку доказательств: вход → ответы стенда → финализация памяти → триггер → вердикт.
- Считать Attack Success Rate (ASR) по числу успешных попыток.
- Настроить зависимости и тесты так, чтобы прогон сценария проверялся на mock HTTP без живого стенда.

Не входит в этот change:

- другие типы атак, другие стенды и абстракция произвольного агента;
- LLM-as-a-judge, генерация сценариев, адаптивное планирование;
- UI / dashboard и HTML-отчёт;
- запуск и управление docker compose стенда;
- чтение HTML-страницы памяти через SSO (`:8501/memory`).

## Capabilities

### New Capabilities

- `attack-cli`: запуск атаки из командной строки, конфигурация цели и ключа, оркестрация шагов сценария.
- `memory-poisoning`: фиксированный сценарий внедрения инструкции в память через публичный чат-API стенда, финализация сессии и проверка цели.
- `attack-report`: CLI-отчёт с вердиктом, ASR, шагами и доказательствами.

### Modified Capabilities

Нет.

## Impact

Появляется исполняемый пакет Python вместо заглушки `main.py`. Добавляются зависимости: HTTP-клиент, модели данных, оркестрация сценария, pytest, ruff. Стенд остаётся внешним: Red Alert ходит только на `agent-api` (`/v1/chat/completions`, `/v1/sessions/{id}/finalize`). Секреты не попадают в репозиторий: ключ атакующего и ключ жертвы задаются аргументами или переменными окружения. Это два разных тестовых пользователя стенда (`client1001` и `client1002`).
