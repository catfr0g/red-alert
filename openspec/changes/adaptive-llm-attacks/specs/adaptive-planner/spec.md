## ADDED Requirements

### Requirement: Payload пишет свой LLM Red Alert

СИСТЕМА ДОЛЖНА (MUST) перед каждым inject вызвать OpenAI-совместимый чат-API планировщика (`OPENAI_BASE_URL`, `OPENAI_API_KEY`, `MODEL`, `MAX_TOKENS`) и отправить на стенд только полученный текст пользовательского сообщения.

#### Scenario: Первый inject берёт текст у планировщика

- **WHEN** начинается попытка `memory-poisoning`
- **THEN** система сначала вызывает планировщик, затем отправляет его ответ как единственное payload-сообщение атакующего в новой сессии A

#### Scenario: Повтор inject после неудачного finalize

- **WHEN** finalize не вернул usable global-политику и лимит inject не исчерпан
- **THEN** система снова вызывает планировщик, передаёт ему факты последнего finalize и отправляет новый сгенерированный текст в новой сессии A

#### Scenario: Следующая попытка видит исход предыдущей

- **WHEN** выполняется вторая попытка после первой
- **THEN** запрос планировщика содержит краткую заметку о результате первой попытки

#### Scenario: Ошибка планировщика обрывает попытку

- **WHEN** вызов LLM планировщика завершается ошибкой сети, HTTP 4xx/5xx или пустым текстом
- **THEN** попытка неуспешна, шаг `adapt` содержит ошибку, inject на стенд в этом цикле не выполняется

### Requirement: Планировщик не подменяет стенд

СИСТЕМА ДОЛЖНА (MUST) вызывать LLM планировщика отдельно от `agent-api`: другой базовый URL и другой ключ. Ключ планировщика не передаётся стенду.

#### Scenario: Разные контуры

- **WHEN** система генерирует payload и затем шлёт его на стенд
- **THEN** запрос планировщика идёт на `OPENAI_BASE_URL` с `OPENAI_API_KEY`, а запрос стенда — на `RED_ALERT_TARGET` с ключом атакующего
