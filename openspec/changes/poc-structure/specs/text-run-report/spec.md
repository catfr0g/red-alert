# Возможность: текстовый отчёт прогона

## ADDED Requirements

### Requirement: отчёт выводится в текстовом pytest-подобном формате

CLI ДОЛЖЕН (MUST) печатать один текстовый отчёт для одного запуска сценария
memory-poisoning. Отчёт ДОЛЖЕН содержать имя сценария, итоговый статус,
нумерованные шаги payload, finalize и trigger, а также короткое резюме
условия проверки.

JSON-формат, опция --report и обязательная запись отчёта в файл в текущем
change не поддерживаются.

#### Scenario: Отчёт об успешном воспроизведении

- **КОГДА** verifier возвращает success
- **ТОГДА** CLI выводит pytest-подобный успешный статус и доказательства
  последовательности payload, finalize и trigger

#### Scenario: Отчёт о невоспроизведённой атаке

- **КОГДА** verifier возвращает not_reproduced
- **ТОГДА** CLI выводит статус невоспроизведения, trigger-ответ и причину,
  по которой regex-цель не достигнута

#### Scenario: Отчёт об ошибке

- **КОГДА** verifier возвращает error
- **ТОГДА** CLI выводит статус ошибки, выполненные шаги и безопасное описание
  первой ошибки

### Requirement: отчёт сохраняет причинно-следственную цепочку

Для каждого выполненного шага отчёт ДОЛЖЕН (MUST) показывать имя операции,
session_id, HTTP-статус, результат шага и текстовый ответ или причину ошибки.
Порядок шагов в отчёте ДОЛЖЕН совпадать с порядком отправки запросов.

#### Scenario: Частичный прогон

- **КОГДА** ошибка произошла на payload или finalize
- **ТОГДА** отчёт показывает уже выполненные шаги, отмечает остановку и не
  создаёт видимость выполнения пропущенного trigger

#### Scenario: Доказательство финализации

- **КОГДА** finalize вернул успешный текстовый ответ
- **ТОГДА** отчёт включает этот ответ между payload и trigger как отдельный
  шаг доказательства

### Requirement: отчёт редактирует чувствительные данные

Reporter ДОЛЖЕН (MUST) заменять значение Authorization на REDACTED. Он НЕ
ДОЛЖЕН печатать API-ключ, внутренние токены или секреты из конфигурации. Тексты
payload и ответов могут показываться как доказательства, но должны проходить
единый redaction перед выводом.

#### Scenario: Безопасный вывод запроса

- **КОГДА** трассировка содержит заголовок Authorization
- **ТОГДА** в отчёте отображается только REDACTED

#### Scenario: Безопасный вывод ошибки

- **КОГДА** HTTP-клиент вернул ошибку с телом ответа или диагностикой
- **ТОГДА** reporter выводит безопасное описание ошибки без значения API-ключа
