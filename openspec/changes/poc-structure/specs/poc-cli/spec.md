# Возможность: CLI запуска PoC

## ADDED Requirements

### Requirement: CLI запускает поддержанный сценарий

Система ДОЛЖНА (MUST) предоставлять установленную команду
red-alert attack с обязательным параметром --scenario. В текущем PoC
поддерживается только значение memory-poisoning. Адрес стенда не передаётся
через --target и фиксирован как
http://localhost:8600/v1/chat/completions.

#### Scenario: Успешный запуск команды

- **КОГДА** пользователь выполняет red-alert attack --scenario
  memory-poisoning с настроенным API-ключом
- **ТОГДА** CLI запускает один сценарий, печатает текстовый отчёт и возвращает
  код 0 при статусе success

#### Scenario: Неизвестный сценарий

- **КОГДА** пользователь передаёт значение --scenario, отличное от
  memory-poisoning
- **ТОГДА** CLI завершается с ошибкой аргументов, не обращается к стенду и
  печатает понятное сообщение о поддержанных значениях

#### Scenario: Отсутствует обязательный параметр

- **КОГДА** пользователь запускает red-alert attack без --scenario
- **ТОГДА** CLI завершается с ошибкой аргументов и не выполняет HTTP-запросов

### Requirement: CLI отражает результат прогона кодом завершения

Система ДОЛЖНА (MUST) возвращать 0 для success, 1 для not_reproduced и 2 для
error либо ошибки конфигурации или аргументов. Ни один технический сбой не
может завершиться кодом успешной атаки.

#### Scenario: Атака не воспроизведена

- **КОГДА** сценарий завершён технически успешно, но trigger не достиг
  проверяемой цели
- **ТОГДА** CLI печатает отчёт со статусом not_reproduced и возвращает код 1

#### Scenario: Ошибка запуска

- **КОГДА** отсутствует API-ключ или обязательный HTTP-шаг завершился ошибкой
- **ТОГДА** CLI печатает отчёт со статусом error и возвращает код 2

### Requirement: CLI не раскрывает секреты

CLI ДОЛЖЕН (MUST) получать API-ключ только из runtime-конфигурации, не требовать
его в payload сценария и не печатать значение заголовка Authorization в отчёте,
ошибке или диагностическом выводе.

#### Scenario: Секрет присутствует в конфигурации

- **КОГДА** сценарий выполняется с валидным API-ключом
- **ТОГДА** запрос получает Bearer-заголовок, а в трассировке и отчёте значение
  ключа заменяется на REDACTED
