# Глоссарий терминов

> Простые рабочие определения для кейса про проверку AI-агентов.
> Английские варианты оставлены для поиска в документации и обсуждения с
> технической командой. Близкие термины объединены, чтобы не повторять одно
> и то же определение несколько раз.

## 1. Система и состояние

| Термин | Русские синонимы | Английские варианты | Простое объяснение | Как используется в кейсе |
|---|---|---|---|---|
| **AI-агент** | агент; автономный помощник | AI agent; autonomous agent | Программа с ИИ-моделью, которая может сама выбрать следующий шаг, вызвать инструмент и выполнить действие. | Объект проверки. Интеллектуальный ассистент из кейса может быть менее самостоятельным вариантом такого агента. |
| **Агентная система** | система с агентом; система вокруг агента | agentic system | Вся система вокруг модели: входы, память, правила, инструменты, состояние и логи. | Проверяем не только модель, а весь этот программный контур. |
| **Контекст** | рабочий контекст; доступная информация | context | Всё, что агент видит перед очередным решением: запрос, историю, память, инструкции и результаты инструментов. | Атака может подменить или дополнить контекст вредной инструкцией. |
| **Память** | постоянная память; долговременная память | persistent memory; long-term memory | Данные, которые сохраняются после завершения сессии и используются позже. | В память могут попасть ложные сведения или вредные инструкции. |
| **Состояние** | текущее состояние; данные состояния | state | Данные и настройки, от которых зависит дальнейшее поведение системы. Память — один из элементов состояния. | Сравниваем состояние до и после атаки и проверяем его влияние на будущие действия. |
| **Сессия** | сеанс; отдельный диалог | session | Один цикл общения пользователя с агентом. | Проверяем, может ли атака из одной сессии сработать в следующей. |
| **Изоляция данных** | разделение пользователей; изоляция клиентов | user isolation; tenant isolation | Правило, по которому один пользователь не видит память, данные и права другого. | Нарушение изоляции может превратить атаку одного пользователя в атаку на других. |
| **Права агента** | разрешённые действия; политика доступа | permissions; access policy | Список того, что агенту разрешено читать, менять и вызывать. | Проверяем, может ли атака обойти эти ограничения или повлиять на выбор разрешённого действия. |

## 2. Атаки и модели угроз

| Термин | Русские синонимы | Английские варианты | Простое объяснение | Как используется в кейсе |
|---|---|---|---|---|
| **AI red teaming** | атакующее тестирование ИИ; проверка ИИ на атаки | AI red teaming; LLM red teaming | Проверка AI-системы как атакующий: подаём специально подготовленные входы и смотрим, удалось ли обойти защиту. | Текущий подход, который в основном оценивает ответ модели. |
| **Agentic red teaming** | атакующее тестирование агентов; проверка агентной системы | agentic red teaming; agent red teaming | Та же проверка, но для всей цепочки агента: память, решения, инструменты, состояние и будущие сессии. | Целевой подход нашего прототипа. |
| **Модель угроз** | описание угроз; карта угроз | threat model; threat modeling | Описание того, кого защищаем, кто атакует, чем он может воспользоваться и какой вред возможен. | Помогает выбрать каналы атаки, цели и сценарии тестирования. |
| **Поверхность атаки** | точки атаки; доступные входы | attack surface | Все места, через которые можно повлиять на систему. | Сюда входят запросы, документы, веб-страницы, результаты инструментов, память и вызовы инструментов. |
| **Prompt injection** | внедрение инструкции; вредная инструкция | prompt injection; prompt attack | Текст, который пытается заставить модель сделать то, чего она не должна делать. Косвенный вариант приходит через документ, веб-страницу или результат инструмента. | Может изменить контекст, записаться в память и повлиять на будущие действия. |
| **Отравление памяти** | заражение памяти; вредная запись в память | memory poisoning; memory injection | Запись в память ложной или вредной информации, которая повлияет на будущие решения агента. | Один из главных сценариев кейса. |
| **Компрометация состояния** | изменение состояния; захват состояния | state compromise; state tampering | Состояние изменилось так, что агент начинает действовать в интересах атакующего или нарушает правила. | Может включать изменение памяти, контекста, прав или текущего процесса. |
| **Атакующая цепочка** | многошаговая атака; последовательность атаки | attack chain; multi-step attack | Цель достигается несколькими шагами: доставка вредного ввода, запись, срабатывание и действие. | Прототип должен находить и показывать всю цепочку, а не только последний ответ. |
| **Payload** | вредная нагрузка; атакующий ввод | payload; malicious input | Конкретный текст, документ, страница или данные, через которые доставляется атака. | Используется для проверки разных каналов доставки. |
| **Триггер** | условие срабатывания; сигнал запуска | trigger | Запрос или условие, которое активирует ранее сохранённую вредную инструкцию. | Может появиться в другой сессии или у другого пользователя. |
| **Распространение атаки** | дальнейшее распространение; перенос компрометации | attack propagation; propagation | Случай, когда уже успешная атака влияет на новые сессии, пользователей, инструменты или действия. | Нужно проверить, остаётся ли атака локальной или выходит за пределы исходной сессии. |
| **MITRE ATLAS** | база техник атак на ИИ | MITRE ATLAS | Справочник с описаниями способов атак на системы машинного обучения и ИИ. | Используется как источник для модели угроз и набора сценариев. |

## 3. Инструменты, выполнение и наблюдение

| Термин | Русские синонимы | Английские варианты | Простое объяснение | Как используется в кейсе |
|---|---|---|---|---|
| **Инструмент** | внешняя функция; подключённый сервис | tool; external tool | Функция, API или сервис, который агент вызывает для получения данных или выполнения действия. | Вызов инструмента может стать результатом атаки. |
| **Вызов инструмента** | запрос к инструменту; вызов функции | tool calling; function calling | Просьба агента к приложению запустить инструмент с заданными параметрами. | Фиксируем, какой инструмент был выбран и что ему передали. |
| **Выбор инструмента** | решение о вызове; выбор функции | tool selection | Решение агента о том, какой инструмент использовать следующим. | Атака может незаметно направить агента к неправильному инструменту. |
| **Аргументы инструмента** | параметры; входные данные инструмента | tool arguments; parameters | Значения, которые агент передаёт инструменту при вызове. | Даже правильный инструмент может стать опасным из-за изменённых аргументов. |
| **Результат инструмента** | ответ инструмента; выходные данные | tool result; tool output | Данные, которые вернул внешний инструмент. | Результат снова попадает в контекст и сам может содержать вредную инструкцию. |
| **Тестовый контур** | тестовая обвязка; стенд | harness; test harness | Слой, который подаёт входы, управляет сессиями, перехватывает вызовы и запускает проверки. | Через него автоматизируем полный цикл атаки и безопасно повторяем тесты. |
| **Трассировка** | журнал шагов; запись выполнения | trace; execution trace | Запись того, что происходило по шагам: входы, решения, вызовы, ответы и изменения состояния. | Нужна, чтобы доказать, как именно прошла атака. |
| **Сравнение состояния** | разница состояния; сравнение до и после | state diff; state comparison | Сравнение состояния до и после шага или атаки. | Показывает, что именно записалось в память или изменилось в системе. |
| **Повторный запуск** | воспроизведение; повтор теста | replay; rerun | Запуск того же сценария ещё раз с теми же условиями. | Нужен для проверки находки и сравнения версий агента. |
| **Снимок состояния** | копия состояния; контрольная точка | snapshot; checkpoint | Сохранённая копия памяти или состояния, к которой можно вернуться. | Позволяет начинать каждый тест из одинаковой точки. |
| **Сброс** | возврат к началу; восстановление | reset; restore | Возврат тестовой системы к безопасному исходному состоянию. | Нужен между прогонами, чтобы одна атака не влияла на другую. |
| **Песочница** | изолированная среда; тестовая среда | sandbox; isolated environment | Среда, отделённая от production и реальных данных. | Все опасные действия должны выполняться только здесь или через имитации. |
| **Тестовая имитация инструмента** | безопасный инструмент; заглушка | mock; stub; test double | Поддельный инструмент, который принимает вызов и возвращает ответ, но не выполняет реальную операцию. | Заменяет переводы и другие необратимые действия в демо. |
| **Наблюдаемость** | видимость работы системы; доступ к логам | observability; visibility | Возможность увидеть и понять, что происходило внутри системы. | Без неё нельзя надёжно подтвердить скрытую компрометацию. |

## 4. Цели, оценка и результаты

| Термин | Русские синонимы | Английские варианты | Простое объяснение | Как используется в кейсе |
|---|---|---|---|---|
| **Цель атаки** | желаемый результат атаки; задача атакующего | attack goal; objective | То, чего хочет добиться атакующий: запись в память, вызов инструмента, утечка данных или действие в новой сессии. | Для каждой атаки заранее задаём проверяемую цель. |
| **Условие успеха** | критерий успеха; проверка результата | success predicate; success criteria | Чёткое правило, по которому решаем, достигнута цель или нет. | Лучше проверять фактическое состояние и вызовы, а не только текст ответа. |
| **ASR** | доля успешных атак | Attack Success Rate | Процент успешных попыток: `успешные попытки / все попытки × 100%`. | Основная метрика кейса; точные правила подсчёта нужно согласовать. |
| **Находка** | результат проверки; уязвимость | finding; security finding | Зафиксированная проблема или успешная атака с описанием и доказательствами. | Из находок формируется отчёт для департамента кибербезопасности. |
| **Доказательство** | подтверждение; материалы атаки | evidence; proof | Данные, по которым другой специалист может проверить результат: payload, шаги, трассировка и изменения состояния. | Делает находку воспроизводимой и убедительной. |
| **Ложное срабатывание** | ошибочная находка; лишняя тревога | false positive; FP | Система сообщила об атаке, хотя цель на самом деле не была достигнута. | Нужно контролировать, чтобы отчётам можно было доверять. |
| **Пропущенная атака** | нераспознанная атака; пропуск | false negative; FN | Система не заметила атаку, которая на самом деле сработала. | Особенно опасно при проверке памяти и будущих сессий. |
| **Контрольный результат** | базовый результат; контрольный прогон | baseline; baseline run | Результат, с которым сравниваем новый прототип или новую версию агента. | Нужен для сравнения с текущими инструментами и предыдущими версиями. |
| **Регрессионный тест** | повторная проверка; тест на возврат ошибки | regression test | Повторяемый тест, который показывает, не вернулась ли уже исправленная проблема. | Найденные атаки можно запускать после каждого изменения агента. |
| **Отчёт** | отчёт о проверке; отчёт о red teaming | red-team report; security report | Итоговый документ: сценарий, шаги, цель, ASR, доказательства, риск и рекомендации. | Основной результат работы для департамента кибербезопасности. |

## 5. Как связаны термины

```text
Канал доставки
  → вредный ввод или prompt injection
  → контекст или память агента
  → выбор инструмента и его аргументы
  → результат и изменение состояния
  → триггер в следующей сессии
  → цель атаки, доказательства и отчёт
```
